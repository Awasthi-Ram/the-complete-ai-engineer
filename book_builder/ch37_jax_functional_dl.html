1. The Paradigm Shift: Imperative OOP vs. Pure Functional Programming

For over a decade, deep learning frameworks (Torch, TensorFlow 1.x/2.x, PyTorch) have adhered to imperative, object-oriented paradigms. In PyTorch, models are stateful classes inheriting from torch.nn.Module that encapsulate mutable parameters. Calling optimizer.step() modifies parameter arrays in-place in GPU memory. While intuitive for Python programmers, in-place state mutation imposes severe constraints on compilers:

  • Aliasing and In-Place Side Effects: Compilers cannot easily prove that two pointers do not alias the same memory buffer, preventing aggressive instruction reordering and automatic parallelization.
  • Complex Distributed Checkpointing: Tracking mutable object state across distributed workers requires complex orchestration, hooks, and pickling mechanisms.
  • Dynamic Control Flow Barriers: Compiling imperative Python code into static accelerator kernels requires tracing engines to infer whether variable mutations affect subsequent computational branches.

Developed by Google Research and adopted by Google DeepMind (powering Gemini, AlphaFold 3, and PaLM), JAX re-envisions deep learning as Pure Functional Programming over Immutable Multi-Dimensional Arrays:

  1. Pure Functions: A function $f(x)$ depends strictly on its explicit input arguments, has zero side-effects (it cannot modify global variables or mutate its input buffers), and always yields the exact same return value given identical inputs.
  2. Immutable Arrays (jax.Array): Arrays cannot be modified in-place. If an element is updated, JAX constructs a new array view (optimized by the compiler): $$\mathbf{x}_{\text{new}} = \mathbf{x}.\text{at}[i].\text{set}(v)$$
  3. Explicit Stateless PRNG Architecture: JAX eliminates global random seeds. Every stochastic operation (dropout, weight initialization, sampling) requires explicitly passing and splitting a cryptographic Pseudo-Random Number Generator (PRNG) key.

2. The JAX PRNG Architecture: Splitting Keys Deterministically

In standard NumPy or PyTorch, calling torch.randn(10) advances a hidden global internal state (such as a 624-word Mersenne Twister state vector). In distributed systems or parallel threads, this global mutable state induces non-deterministic race conditions and irreproducible training runs.

JAX abandons global state entirely in favor of Counter-Based Pseudo-Random Number Generation (Threefish / Philox):

$$\text{key} \in \mathbb{N}^{2} \quad (\text{a pair of unsigned 32-bit integers})$$

To generate random numbers, a key must be explicitly split into new statistically independent subkeys using jax.random.split:

import jax
import jax.numpy as jnp

# Initialize the root PRNG key
root_key = jax.random.PRNGKey(42)

# Split root key into a key for subsequent steps and a subkey for active consumption
key, subkey1, subkey2 = jax.random.split(root_key, num=3)

# Generate independent stochastic samples
x = jax.random.normal(subkey1, shape=(4, 4))
dropout_mask = jax.random.bernoulli(subkey2, p=0.8, shape=(4, 4))

🚨 The JAX Key Reuse Trap:
Reusing the exact same PRNG key across multiple stochastic calls generates identical random numbers! If the same key is passed to both Layer 1 and Layer 2 for dropout, both layers drop the exact same neuron coordinates, destroying statistical independence and damaging model generalization.

3. The Four Composable Function Transformations

JAX's expressive power derives from four pure mathematical function transformations that can be arbitrarily composed in any order:

3.1 jax.grad and jax.value_and_grad: Reverse-Mode Autodiff

Transforms any pure scalar-valued function into its analytical gradient function via Reverse-Mode Automatic Differentiation (Vector-Jacobian Products):

$$f: \mathbb{R}^d \to \mathbb{R} \xrightarrow{\text{jax.grad}} \nabla f: \mathbb{R}^d \to \mathbb{R}^d$$

Because JAX transformations are composable, higher-order derivatives require zero special engineering: jax.grad(jax.grad(f)) automatically computes the exact Hessian-vector product!

3.2 jax.jit: Just-In-Time Compilation via XLA

Python executes imperatively line-by-line, causing interpreter overhead and writing intermediate activations back to high-bandwidth memory (HBM/VRAM). jax.jit traces the Python function into an intermediate computational representation called a Jaxpr (JAX Expression) and compiles it into highly optimized native accelerator machine code using XLA (Accelerated Linear Algebra).

⚡ XLA Kernel Fusion: Eliminating the Memory Bandwidth Wall

Consider the elementary sequence: $\mathbf{y} = \operatorname{ReLU}(\mathbf{W}\mathbf{x} + \mathbf{b})$. In eager PyTorch:

  1. Kernel 1 launches: computes $\mathbf{z}_1 = \mathbf{W}\mathbf{x}$, writes $\mathbf{z}_1$ to VRAM.
  2. Kernel 2 launches: reads $\mathbf{z}_1$ from VRAM, adds $\mathbf{b}$, writes $\mathbf{z}_2$ to VRAM.
  3. Kernel 3 launches: reads $\mathbf{z}_2$ from VRAM, applies $\max(0, \mathbf{z}_2)$, writes $\mathbf{y}$ to VRAM.

XLA Kernel Fusion compiles all three operations into a single fused GPU/TPU kernel! The intermediate values $\mathbf{z}_1$ and $\mathbf{z}_2$ are held directly in high-speed registers without ever touching external VRAM, providing a $2\times$ to $4\times$ speedup while drastically slashing memory bandwidth consumption.

3.3 jax.vmap: Automatic Vectorization

Writing batching code manually (handling batch dimensions, matrix slicing, reshaping) is tedious and error-prone. With jax.vmap, an engineer writes the function for a single sample ($\mathbf{x} \in \mathbb{R}^D$), and jax.vmap automatically pushes the batch dimension into SIMD hardware vector instructions without any explicit loops:

$$\text{batched\_fn} = \text{jax.vmap}(f_{\text{single}}, \text{in\_axes}=(0, \text{None}))$$

3.4 jax.pmap: Multi-Device SPMD Parallelism

Replicates computation across multiple physical accelerator chips (GPUs or TPU cores) in a Single-Program Multiple-Data (SPMD) paradigm. Devices execute in lockstep and exchange data via collective communication primitives (such as jax.lax.psum and jax.lax.pmean) mapped directly to hardware interconnects (NVLink or TPU Inter-Chip Networks).

4. PyTrees: The Universal Functional Data Structure

In JAX, model weights, optimizer states, activations, and dataset batches are represented as PyTrees: recursive trees of Python container types (dicts, lists, tuples, namedtuples) whose terminal leaf nodes are multi-dimensional arrays (jax.Array).

Operating on an entire neural network requires no loops over parameter lists. JAX provides tree mapping primitives:

$$\text{new\_params} = \text{jax.tree\_util.tree\_map}(\lambda p, g: p - \eta \cdot g, \text{params}, \text{grads})$$

This single line updates every weight and bias tensor across arbitrary nested model architectures!

✓ Complete Architectural & Numerical Solution

Step 1: Why Dynamic Array Tracers Fail: When dynamic_power is compiled with standard @jax.jit, both arguments x and n are passed as abstract Tracer Objects (specifically ShapedArray(float32[2]) and ShapedArray(int32[])). Tracers know their data type and shape, but hold no concrete numerical values during tracing! When Python reaches if n == 0: or range(n - 1), it attempts to cast the tracer to a boolean via bool(n == 0).   • Call 1 (x1, n=3): First time n=3 is encountered. JAX runs the Python function to trace it. The Python print() statement executes: Tracing invoked for x shape=(2,), n=3! XLA compiles the unrolled graph: $x \times x \times x$. Result returned: $[2^3, 3^3] = \mathbf{[8.0, 27.0]}$. Console output: Tracing invoked for x shape=(2,), n=3! Call 1: [ 8. 27.]
  • Call 2 (x1, n=3): JAX checks its compilation cache. An XLA binary for shape (2,) and static argument n=3 already exists! Python code is completely skipped; the compiled machine code executes directly. No trace statement is printed! Console output: Call 2: [ 8. 27.]

Step 3: The Cost of Static Arguments: Every distinct value passed to a static argument triggers full XLA tracing and binary compilation. If an engineer passes a dynamic loop index or step number as a static argument across 10,000 steps, JAX will re-compile 10,000 separate XLA binaries, exhausting host memory and halting training in compile-time deadlock!

QUESTION (Mathematical Proof of Auto-Vectorization Equivalence under jax.vmap): Consider a single-sample linear model $f: \mathbb{R}^D \to \mathbb{R}^K$ defined as:

$$f(\mathbf{x}; \mathbf{W}, \mathbf{b}) = \mathbf{W}\mathbf{x} + \mathbf{b}, \quad \mathbf{W} \in \mathbb{R}^{K \times D}, \mathbf{b} \in \mathbb{R}^K, \mathbf{x} \in \mathbb{R}^D$$

Prove that applying jax.vmap(f, in_axes=(0, None, None)) over a batch matrix $\mathbf{X} \in \mathbb{R}^{B \times D}$ (where row $i$ is $\mathbf{x}_i^T$) produces an output $\mathbf{Y} \in \mathbb{R}^{B \times K}$ that is mathematically identical to the batched matrix expression $\mathbf{X}\mathbf{W}^T + \mathbf{1}_B \mathbf{b}^T$.

For a scalar loss $\mathcal{L} = \sum_{i=1}^B \ell(f(\mathbf{x}_i))$, prove that the functional gradient $\nabla_\mathbf{W} \mathcal{L}$ computed via jax.grad(lambda W: jnp.sum(vmap(f, ...)(X, W, b))) exactly satisfies: $$\nabla_\mathbf{W} \mathcal{L} = \sum_{i=1}^B \nabla_{\mathbf{W}} \ell(f(\mathbf{x}_i)) = \mathbf{G}^T \mathbf{X}, \quad \text{where } \mathbf{G}_{i, :} = \nabla_{\hat{\mathbf{y}}_i} \ell$$
✓ Complete First-Principles Mathematical Proof

Step 1: Vectorization Equivalence: Let $\mathbf{X} \in \mathbb{R}^{B \times D}$ be the batch matrix whose rows are $\mathbf{x}_1^T, \dots, \mathbf{x}_B^T$. By definition, jax.vmap(f, in_axes=(0, None, None)) evaluates $f$ on each row slice independently: $$\operatorname{vmap}(f)(\mathbf{X}, \mathbf{W}, \mathbf{b}) = \begin{bmatrix} f(\mathbf{x}_1; \mathbf{W}, \mathbf{b})^T \\ f(\mathbf{x}_2; \mathbf{W}, \mathbf{b})^T \\ \vdots \\ f(\mathbf{x}_B; \mathbf{W}, \mathbf{b})^T \end{bmatrix} \in \mathbb{R}^{B \times K}$$ For any row $i \in \{1, \dots, B\}$: $$f(\mathbf{x}_i; \mathbf{W}, \mathbf{b}) = \mathbf{W}\mathbf{x}_i + \mathbf{b} \implies f(\mathbf{x}_i; \mathbf{W}, \mathbf{b})^T = (\mathbf{W}\mathbf{x}_i + \mathbf{b})^T = \mathbf{x}_i^T \mathbf{W}^T + \mathbf{b}^T$$ Stacking these rows across all $B$ samples: $$\begin{bmatrix} \mathbf{x}_1^T \mathbf{W}^T + \mathbf{b}^T \\ \mathbf{x}_2^T \mathbf{W}^T + \mathbf{b}^T \\ \vdots \\ \mathbf{x}_B^T \mathbf{W}^T + \mathbf{b}^T \end{bmatrix} = \begin{bmatrix} \mathbf{x}_1^T \\ \mathbf{x}_2^T \\ \vdots \\ \mathbf{x}_B^T \end{bmatrix} \mathbf{W}^T + \begin{bmatrix} \mathbf{b}^T \\ \mathbf{b}^T \\ \vdots \\ \mathbf{b}^T \end{bmatrix} = \mathbf{X}\mathbf{W}^T + \mathbf{1}_B \mathbf{b}^T$$ Thus, vmap transforms the scalar-vector loop into the canonical BLAS-3 batched GEMM $\mathbf{X}\mathbf{W}^T + \mathbf{1}\mathbf{b}^T$. $\quad \blacksquare$

Step 2: Gradient Commutation Proof: Let $\hat{\mathbf{y}}_i = \mathbf{W}\mathbf{x}_i + \mathbf{b}$. The total loss is: $$\mathcal{L}(\mathbf{W}) = \sum_{i=1}^B \ell(\hat{\mathbf{y}}_i)$$ Applying the matrix calculus chain rule to each term: $$d\ell(\hat{\mathbf{y}}_i) = \operatorname{tr}\left(\left(\nabla_{\hat{\mathbf{y}}_i} \ell\right)^T d\hat{\mathbf{y}}_i\right)$$ Since $d\hat{\mathbf{y}}_i = (d\mathbf{W})\mathbf{x}_i$: $$d\ell(\hat{\mathbf{y}}_i) = \operatorname{tr}\left(\left(\nabla_{\hat{\mathbf{y}}_i} \ell\right)^T (d\mathbf{W})\mathbf{x}_i\right) = \operatorname{tr}\left(\mathbf{x}_i \left(\nabla_{\hat{\mathbf{y}}_i} \ell\right)^T d\mathbf{W}\right) = \operatorname{tr}\left(\left(\left(\nabla_{\hat{\mathbf{y}}_i} \ell\right) \mathbf{x}_i^T\right)^T d\mathbf{W}\right)$$ Therefore, the gradient with respect to $\mathbf{W}$ for sample $i$ is the outer product: $$\nabla_\mathbf{W} \ell(\hat{\mathbf{y}}_i) = \left(\nabla_{\hat{\mathbf{y}}_i} \ell\right) \mathbf{x}_i^T \in \mathbb{R}^{K \times D}$$ Summing over all $B$ samples: $$\nabla_\mathbf{W} \mathcal{L} = \sum_{i=1}^B \left(\nabla_{\hat{\mathbf{y}}_i} \ell\right) \mathbf{x}_i^T$$ Define the upstream gradient matrix $\mathbf{G} \in \mathbb{R}^{B \times K}$ where row $i$ is $\left(\nabla_{\hat{\mathbf{y}}_i} \ell\right)^T$. Then: $$\mathbf{G}^T \mathbf{X} = \sum_{i=1}^B \mathbf{g}_i \mathbf{x}_i^T$$ which matches $\nabla_\mathbf{W} \mathcal{L}$ identically! In JAX, autodiff pushes through the vmap transformation by transforming the tangent/cotangent evaluation into batched outer products, proving exact numerical and structural equivalence. $\quad \blacksquare$

Step 1: Mathematical Formulations of JVP and VJP: Let $f: \mathbb{R}^N \to \mathbb{R}^M$ have Jacobian matrix $\mathbf{J}_{ij} = \frac{\partial f_i}{\partial x_j} \in \mathbb{R}^{M \times N}$.

  • Jacobian-Vector Product (JVP / Forward-Mode): Given a tangent vector $\mathbf{v} \in \mathbb{R}^N$, the JVP computes the directional derivative: $$\operatorname{JVP}(f, \mathbf{x}, \mathbf{v}) = \mathbf{J} \mathbf{v} = \lim_{\epsilon \to 0} \frac{f(\mathbf{x} + \epsilon \mathbf{v}) - f(\mathbf{x})}{\epsilon} \in \mathbb{R}^M$$ Evaluated forward along the computational graph alongside the primal values.
  • Vector-Jacobian Product (VJP / Reverse-Mode): Given a cotangent (upstream gradient) vector $\mathbf{u} \in \mathbb{R}^M$, the VJP computes the backpropagated adjoint: $$\operatorname{VJP}(f, \mathbf{x}, \mathbf{u}) = \mathbf{u}^T \mathbf{J} = \mathbf{J}^T \mathbf{u} \in \mathbb{R}^N$$ Evaluated in reverse along the transposed computational graph from outputs to inputs.

Step 2: Deep Classifier Complexity ($N = 10^7, M = 1$): We wish to compute $\nabla_\mathbf{x} f \in \mathbb{R}^N$ (which is the Jacobian $\mathbf{J}^T$).

  • Using Forward-Mode (JVP): Each forward JVP call computes $\mathbf{J} \mathbf{v}$ for a single direction $\mathbf{v}$. To reconstruct the $N$ partial derivatives $\frac{\partial f}{\partial x_1}, \dots, \frac{\partial f}{\partial x_N}$, we must evaluate JVPs along each canonical basis vector $\mathbf{e}_1, \dots, \mathbf{e}_N$: $$\text{Evaluations Required} = N = 10,000,000 \text{ forward passes!}$$ This would require weeks of compute.

Choosing cotangent $\mathbf{u} = [1.0] \in \mathbb{R}^1$: $$\mathbf{u}^T \mathbf{J} = 1.0 \times \mathbf{J} = \nabla_\mathbf{x} f$$ The entire gradient vector of all $10^7$ parameters is recovered in exactly $1$ single reverse pass! Complexity is $\mathcal{O}(1)$ function evaluations. $\quad \blacksquare$

Step 3: NeRF Coordinate Traversal ($N = 3, M = 10^5$): Consider finding the rate of change of $10^5$ output points with respect to camera ray direction $\mathbf{v} \in \mathbb{R}^3$:

  • Using Forward-Mode (JVP): Passing the ray velocity vector $\mathbf{v} \in \mathbb{R}^3$ directly into jax.jvp(f, (x,), (v,)) computes the exact derivative across all $M = 10^5$ output points simultaneously in $1$ forward pass! Complexity is $\mathcal{O}(1)$.
  • Using Reverse-Mode (VJP): To obtain the directional derivative across all $M$ outputs via backpropagation without JVP, one would need to seed cotangents for each of the $M = 10^5$ outputs, requiring $10^5$ backward passes! Forward-mode is $\mathbf{100,000\times}$ more efficient. $\quad \blacksquare$

Problem 3.7.7 Medium Google DeepMind

QUESTION (The JIT Python Control Flow Concretization Trap): An engineer writes the following function and tests it under @jax.jit:

import jax
import jax.numpy as jnp

@jax.jit
def process_data(x, threshold=0.0):
    if jnp.sum(x) > threshold:
        return x * 2.0
    else:
        return x * 0.0

print(process_data(jnp.array([1.0, 2.0])))

What happens when this code is executed, and what is the proper functional remedy?

  • (A) It prints [2.0, 4.0] because 1.0 + 2.0 = 3.0 > 0.0 is evaluated during compilation.
  • (B) It crashes with ConcretizationTypeError because Python's if statement attempts to evaluate the concrete truth value of an abstract tracer jnp.sum(x) > threshold at compile time. The remedy is replacing the Python branch with jax.lax.cond.
  • (C) It crashes with FloatingPointError because threshold defaults to 0.0, causing a division by zero in the branch predictor.
  • (D) JAX automatically falls back to eager Python mode without compilation whenever a branch condition is encountered.
✓ Correct Answer: (B)

Exhaustive Distractor Analysis:

  • (B) is CORRECT: During @jax.jit tracing, x is replaced by an abstract tracer ShapedArray(float32[2]). The expression jnp.sum(x) > threshold evaluates to a boolean tracer ShapedArray(bool[]). When Python's native if keyword executes, it internally calls __bool__() on the condition to decide which branch of Python bytecode to execute. Because the tracer contains no concrete values, JAX raises jax.errors.ConcretizationTypeError. To compile data-dependent branches into XLA, one must use jax.lax.cond(pred, true_fun, false_fun, *operands), which compiles both branches into an XLA conditional operator (kSelect) evaluated natively on the accelerator.
  • (A) is INCORRECT: Assumes JAX evaluates array values during tracing. Tracing only inspects types and shapes, never numerical values.
  • (C) is INCORRECT: There is no division operation anywhere in the function.
  • (D) is INCORRECT: JAX never silently falls back to eager Python mode inside @jax.jit; it strictly enforces compilation or throws a hard exception.

Problem 3.7.8 Hard Google TPU Systems

QUESTION (SPMD Sharding and Collective Reduction with jax.pmap): An engineer is scaling training across an 8-device TPU pod slice using jax.pmap:

import jax
import jax.numpy as jnp

@jax.pmap
def parallel_loss_step(x, w):
    # x has shape (8, 32, 128) - 8 devices, batch 32 per device
    # w has shape (128, 64)
    pred = jnp.dot(x, w)
    loss = jnp.mean(pred ** 2)
    # Goal: synchronize mean loss across all 8 devices
    return loss

devices = jax.local_devices() # 8 TPU cores
x = jnp.ones((8, 32, 128))
w = jnp.ones((128, 64))
# Call parallel_loss_step(x, w)

Why will calling parallel_loss_step(x, w) fail or produce incorrect multi-device behavior, and how must the code be corrected?

  • (A) w has leading dimension 128 instead of 8; jax.pmap maps the leading dimension of every passed argument across devices by default. Therefore, w must be replicated across devices or marked with in_axes=(0, None), and cross-device synchronization requires jax.lax.pmean(loss, axis_name=...).
  • (B) TPU pods do not support dot products of dimension 128; dimensions must be powers of two greater than 256.
  • (C) jax.pmap requires models to be written as PyTorch modules.
  • (D) The code runs correctly and automatically executes a Ring All-Reduce across all 8 TPUs without any collective primitives.
✓ Correct Answer: (A)

Exhaustive Systems Architecture Analysis:

  • (A) is CORRECT: By default, jax.pmap assumes that the leading dimension (axis 0) of all positional input arguments corresponds to the device mesh dimension ($N = 8$). While x has shape (8, 32, 128) and splits evenly (32 samples per device), w has shape (128, 64). JAX attempts to slice w along axis 0 into 8 chunks of size $16 \times 64$, meaning each TPU receives an incomplete fragment of the weight matrix instead of the full model! To fix this, the engineer must either:
    1. Pass in_axes=(0, None) to jax.pmap so that w is broadcast to all devices without sharding.
    2. Explicitly replicate w across devices using jax.device_put_replicated(w, devices).
    Furthermore, without jax.lax.pmean(loss, axis_name='dev'), each device simply returns its own independent local scalar loss without any cross-accelerator reduction!
  • (B) is INCORRECT: TPUs handle arbitrary matrix dimensions (padding internally to $128 \times 128$ systolic array tiles).
  • (C) is INCORRECT: JAX is completely independent of PyTorch.
  • (D) is INCORRECT: jax.pmap does not automatically insert collective communication reductions unless explicitly invoked via jax.lax.psum or jax.lax.pmean with a bound axis_name.

Code Lab 3.7 — Deep Neural Network Training in Pure JAX

🔗 View in GitHub: part3_neural_networks/ch37_jax_functional/jax_mlp.py

import jax
import jax.numpy as jnp

# 1. Initialize parameters as a pure PyTree (nested dict of immutable arrays)
def init_mlp_params(layer_sizes, key):
    keys = jax.random.split(key, len(layer_sizes) - 1)
    params = []
    for k, (din, dout) in zip(keys, zip(layer_sizes[:-1], layer_sizes[1:])):
        # He / Kaiming normal initialization: std = sqrt(2 / din)
        w = jax.random.normal(k, (din, dout)) * jnp.sqrt(2.0 / din)
        b = jnp.zeros((dout,))
        params.append({"w": w, "b": b})
    return params

# 2. Forward pass on a SINGLE sample (Pure mathematics: no batch dimension!)
def forward_single(params, x):
    for layer in params[:-1]:
        x = jax.nn.relu(jnp.dot(x, layer["w"]) + layer["b"])
    # Linear output projection
    return jnp.dot(x, params[-1]["w"]) + params[-1]["b"]

# 3. Vectorize across batch dimension automatically using vmap!
forward_batch = jax.vmap(forward_single, in_axes=(None, 0))

# 4. Pure Loss Function (Mean Squared Error)
def loss_fn(params, x_batch, y_batch):
    preds = forward_batch(params, x_batch)
    return jnp.mean((preds - y_batch) ** 2)

# 5. JIT-compiled update step with reverse-mode autodiff & PyTree gradient descent
@jax.jit
def update_step(params, x_batch, y_batch, lr=0.01):
    loss, grads = jax.value_and_grad(loss_fn)(params, x_batch, y_batch)
    # Pure functional parameter update via tree_map (zero in-place mutation)
    new_params = jax.tree_util.tree_map(lambda p, g: p - lr * g, params, grads)
    return new_params, loss

if __name__ == "__main__":
    key = jax.random.PRNGKey(42)
    k_init, k_data_x, k_data_y = jax.random.split(key, 3)

    # 4-layer MLP: 4 -> 32 -> 16 -> 1
    params = init_mlp_params([4, 32, 16, 1], k_init)
    x = jax.random.normal(k_data_x, (128, 4))
    y = jax.random.normal(k_data_y, (128, 1))

    print(f"JAX Device: {jax.devices()[0]}")
    print("Initial Batched Output Shape:", forward_batch(params, x).shape)

    for epoch in range(5):
        params, loss = update_step(params, x, y, lr=0.05)
        print(f"Epoch {epoch+1:02d}: JIT-Compiled Loss = {loss:.6f}")
