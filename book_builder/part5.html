Chapter 5.1

Text to Numbers

NLP Foundations, N-Grams, TF-IDF & Distributed Word2Vec Embeddings ✦

"You shall know a word by the company it keeps."

— J.R. Firth (1957)

Foundation

Neural networks process continuous tensors, not strings of characters. Natural Language Processing (NLP) is the discipline of mapping human symbolic language into continuous geometric vector spaces where semantic similarity corresponds to geometric proximity.

1. The Evolution of Word Representations

  • One-Hot Encoding: Sparse vectors of vocabulary length $|V|$. Massive memory footprint ($|V| \ge 50,000$), completely orthogonal (no semantic relationship between "cat" and "kitten").
  • TF-IDF: Weighs term frequency by inverse document frequency: $\text{TF-IDF}(t, d) = \text{TF}(t, d) \cdot \log\left(\frac{N}{\text{DF}(t)}\right)$. Captures keyword importance but lacks sequence context.
  • Word2Vec (Mikolov et al., 2013): Dense embeddings in $\mathbb{R}^{300}$ trained via Skip-Gram with Negative Sampling. Learns linear semantic vector algebra: $\vec{v}_{\text{King}} - \vec{v}_{\text{Man}} + \vec{v}_{\text{Woman}} \approx \vec{v}_{\text{Queen}}$.

import collections

def get_stats(vocab):
    pairs = collections.defaultdict(int)
    for word, freq in vocab.items():
        symbols = word.split()
        for i in range(len(symbols) - 1):
            pairs[symbols[i], symbols[i + 1]] += freq
    return pairs
Chapter 5.2

The LLM Revolution

Autoregressive Pre-training, Chinchilla Scaling Laws & KV Cache Optimization ✦

"Scale is all you need."

— Empirical AI Maxim

Foundation

Autoregressive Large Language Models (LLMs) are trained on a single objective: Next-Token Prediction. By minimizing cross-entropy loss over trillions of tokens, the network is forced to build internal world models, compress human knowledge, and develop emergent in-context reasoning capabilities.

1. Chinchilla Scaling Laws (Hoffmann et al., 2022)

DeepMind demonstrated that for compute-optimal training, model parameter count $N$ and token count $D$ should scale in equal proportion: $D \approx 20 \times N$. A 7B parameter model should be trained on at least 140 billion tokens; training smaller models on massive token corpora (e.g. LLaMA-3 8B trained on 15 trillion tokens) yields extreme inference efficiency.

2. The KV Cache: Eliminating $O(N^2)$ Inference Redundancy

During generation, each new token attends to all previous tokens. Projecting Keys and Values for every prior token on every forward step wastes quadratic compute. The KV Cache stores calculated Keys and Values in GPU memory:

$$\text{Memory}_{\text{KVCache}} = 2 \times 2 \times n_{\text{layers}} \times n_{\text{heads}} \times d_{\text{head}} \times \text{seq\_len} \times \text{batch\_size} \text{ bytes}$$

🔗 View in GitHub: part5_llms_and_agents/ch52_llm_revolution/kv_cache_attention.py

import torch

class KVCacheManager:
    def __init__(self, batch_size, max_seq_len, n_heads, d_head):
        self.k_cache = torch.zeros(batch_size, n_heads, max_seq_len, d_head)
        self.v_cache = torch.zeros(batch_size, n_heads, max_seq_len, d_head)
        self.pos = 0

    def update(self, new_k, new_v):
        p = self.pos
        self.k_cache[:, :, p:p+1, :] = new_k
        self.v_cache[:, :, p:p+1, :] = new_v
        self.pos += 1
        return self.k_cache[:, :, :self.pos, :], self.v_cache[:, :, :self.pos, :]
Chapter 5.3

Prompt Engineering

In-Context Learning, Chain-of-Thought & Constrained Structured Outputs ✦

"The hottest new programming language is English."

— Andrej Karpathy

Foundation

Prompt engineering is the systematic art and science of steering frozen autoregressive language models toward deterministic, reliable, and verified business outcomes.

1. Core Prompting Strategies

  • Zero-Shot / Few-Shot In-Context Learning: Providing 3–5 representative demonstration pairs in the prompt primes the model's conditional distribution without altering weights.
  • Chain-of-Thought (Wei et al., 2022): Prompting the model with step-by-step intermediate reasoning paths ("Let's think step by step") unlocks multi-step mathematical and symbolic logic.
  • Self-Consistency Majority Voting: Generating $k=5$ stochastic reasoning paths with temperature $T=0.7$ and extracting the consensus mode answer drops reasoning errors by 30%+.

import re
from collections import Counter

def self_consistency_vote(reasoning_paths):
    answers = [
        re.search(r'answer is[:\\s]*([\\w\\d\\.\\-]+)', p, re.I).group(1).lower()
        for p in reasoning_paths if 'answer is' in p
    ]
    return Counter(answers).most_common(1)[0][0]
Chapter 5.4

Fine-Tuning LLMs

LoRA Low-Rank Adaptation, QLoRA 4-bit, SFT & Direct Preference Optimization (DPO) ✦

"Specialization is the key to mastery."

— Industry Engineering Principle

Foundation

Pre-trained models are generalists. Domain-specific production tasks (medical coding, legal drafting, code generation) require specialized adaptation through Supervised Fine-Tuning (SFT) and Preference Alignment.

1. Low-Rank Adaptation (LoRA) Mathematics

Hu et al. (2021) showed that the weight change $\Delta W \in \mathbb{R}^{d \times k}$ during task adaptation has a very low intrinsic rank. Instead of updating full matrix $W_0$, LoRA freezes $W_0$ and injects two low-rank matrices $A \in \mathbb{R}^{r \times k}$ and $B \in \mathbb{R}^{d \times r}$ ($r \ll d$): $$W = W_0 + \Delta W = W_0 + \frac{\alpha}{r} (B \cdot A)$$ $A$ is initialized from a Gaussian distribution and $B$ is initialized to zero, ensuring $\Delta W = 0$ at training initialization.

🔗 View in GitHub: part5_llms_and_agents/ch54_finetuning_lora/lora_layer_from_scratch.py

import torch
import torch.nn as nn
import torch.nn.functional as F

class LoRALinear(nn.Module):
    def __init__(self, in_f, out_f, r=4, alpha=8.0):
        super().__init__()
        self.weight = nn.Parameter(torch.randn(out_f, in_f), requires_grad=False)
        self.scaling = alpha / r
        self.lora_A = nn.Parameter(torch.randn(r, in_f) * (1 / r))
        self.lora_B = nn.Parameter(torch.zeros(out_f, r))

    def forward(self, x):
        return F.linear(x, self.weight) + (x @ self.lora_A.T @ self.lora_B.T) * self.scaling
Chapter 5.5

RAG (Retrieval-Augmented Generation)

Chunking, Dense Vector Databases, HNSW Indexing & Hybrid Search ✦

"Knowledge is of two kinds: we know a subject ourselves, or we know where we can find information upon it."

— Samuel Johnson

Foundation

Parametric memory in LLMs has three fatal production limitations: static knowledge cutoffs, zero visibility into private enterprise databases, and hallucinatory confabulations. RAG connects generative models to dynamic external non-parametric vector databases.

1. Production RAG Architecture

  1. Ingestion & Chunking: Documents are split into semantic chunks (typically 256–512 tokens with 50-token overlap).
  2. Embedding Generation: Chunks are encoded into dense vectors via models like `text-embedding-3-small`.
  3. Vector Indexing: Approximate Nearest Neighbor (ANN) indexing via HNSW (Hierarchical Navigable Small World) graphs yields $O(\log N)$ search latency over millions of vectors.
  4. Hybrid Search & Reranking: Combines dense vector similarity with sparse BM25 keyword search, followed by a Cross-Encoder reranker.
  5. Prompt Augmentation: Top-$k$ context passages are injected into the LLM system prompt for grounded synthesis.

Chapter 5.6

Autonomous AI Agents

The ReAct Framework, Tool Use, Dynamic Memory & Multi-Agent Planning ✦

"Action is the foundational key to all success."

— Pablo Picasso

Foundation

A pure LLM is passive: it answers questions in a single forward pass. An AI Agent is an active autonomous system that perceives its environment, reasons through complex multi-step objectives, invokes external APIs (calculators, SQL databases, bash shells), observes execution outputs, and self-corrects until its goal is verified.

1. The ReAct (Reason + Act) Loop

Yao et al. (2022) established the canonical agent cycle: $$\text{Thought} \to \text{Action} \to \text{Action Input} \to \text{Observation} \to \text{Next Thought} \to \dots \to \text{Final Answer}$$ Interleaving reasoning with environmental action grounds the agent's logic, preventing hallucinated API responses.
