Distributed Vector Search at Scale

Foundation • Core Pillar

1. The Exact k-NN Complexity Wall

In modern enterprise AI systems (Retrieval-Augmented Generation, visual search, and recommendation engines), data is represented as high-dimensional embedding vectors ($d \in [512, 1536]$). Finding the exact $k$-nearest neighbors via a brute-force linear scan (Flat Index) requires evaluating:

$$\text{FLOPs per Query} = N \cdot d \cdot 2$$

For a catalog of $N = 100,000,000$ vectors of dimension $d = 1,536$ in standard IEEE FP32 ($4 \text{ bytes}$):

$$\text{Raw Memory Footprint} = 100 \times 10^6 \times 1,536 \times 4 \text{ bytes} \approx \mathbf{614.4 \text{ Gigabytes of RAM}}!$$

A single query takes over 8 seconds on a multi-core CPU. To achieve interactive sub-15ms search across billions of items, we must abandon exact linear scans in favor of Approximate Nearest Neighbor (ANN) Search, which trades a negligible $1\%$ to $2\%$ drop in recall for a $1,000\times$ speedup.

2. Hierarchical Navigable Small World (HNSW): Malkov & Yashunin, 2018

HNSW is the gold standard graph-based ANN algorithm, deployed in Pinecone, Milvus, Qdrant, and Weaviate. Inspired by the 1D Skip List, HNSW constructs a multi-layer geometric proximity graph:

🌐 The Multi-Layer Proximity Graph Architecture

  • Top Layers ($l_{\max}$): Contain a sparse subset of vectors connected by long-range geometric links. Queries take massive "high-speed jumps" across the global coordinate space. Layer assignment follows an exponential decay: $$l = \lfloor -\ln(\text{uniform}(0, 1)) \cdot m_L \rfloor, \quad \text{where } m_L = \frac{1}{\ln M}$$
  • Bottom Layer (Layer 0): Contains all $N$ vectors connected by dense, short-range local links ($2M$ maximum edges).

The Query Routing Algorithm:

  1. Start at the designated global entry point at top layer $l_{\max}$.
  2. Perform greedy local routing: evaluate distance to all neighbors of the current node; hop to the neighbor closest to the query vector $\mathbf{q}$.
  3. When a local minimum is reached on layer $l$, drop vertically to the same node on layer $l-1$.
  4. Repeat greedy routing until reaching Layer 0, where a bounded beam search of width efSearch discovers the top-$k$ nearest neighbors!

Search Complexity: Reduces search time from linear $O(N)$ down to logarithmic $O(\log N)$! However, storing graph edge lists requires significant auxiliary RAM ($1.5\times$ to $2\times$ raw vector size).

3. Inverted File with Product Quantization (IVF-PQ)

When dataset scale reaches billions of vectors, even storing raw vectors in RAM becomes economically unfeasible. Product Quantization (PQ - Jégou et al., 2011) solves this via lossy vector compression:

The Mechanics of Product Quantization (PQ):

  1. A $d$-dimensional vector is split into $m$ distinct sub-vectors of length $d^* = d/m$ (e.g. A 768-dim vector is split into $m = 64$ sub-vectors of dimension 12).
  2. For each sub-vector space, K-Means clusters the training data into $K = 256$ centroids.
  3. Because $256 = 2^8$, each centroid index fits into exactly 1 single byte (uint8)!
  4. Each sub-vector is replaced by the 1-byte index of its nearest centroid.

The Compression Miracle: A 768-dimensional float32 vector ($3,072 \text{ bytes}$) is compressed into $m = 64$ bytes: a staggering $48\times$ memory reduction!

Asymmetric Distance Computation (ADC): At query time, the query vector $\mathbf{q}$ is NOT quantized. The server computes the distance between $\mathbf{q}$'s sub-vectors and the $256$ codebook centroids once, building a tiny lookup table. Evaluating the distance to a database vector requires only $m$ table lookups and additions—with zero floating-point multiplications!

QUESTION: In Product Quantization (PQ), distance evaluation between an unquantized query vector and quantized database vectors is accelerated via Asymmetric Distance Computation (ADC).

Consider an 8-dimensional space ($d = 8$) divided into $m = 2$ sub-vectors of dimension $d^* = 4$. The query vector is: $$\mathbf{q} = [1.0, \; 2.0, \; -1.0, \; 0.5, \quad 0.0, \; 1.5, \; 2.0, \; -0.5]$$ The trained codebook has $K = 2$ centroids per subspace ($c \in \{0, 1\}$):

  • Subspace 1 Centroids: $\mathbf{c}_{1, 0} = [0.0, 1.0, 0.0, 0.0]$, $\mathbf{c}_{1, 1} = [1.0, 2.0, -1.0, 1.0]$
  • Subspace 2 Centroids: $\mathbf{c}_{2, 0} = [0.0, 1.0, 1.0, 0.0]$, $\mathbf{c}_{2, 1} = [0.0, 2.0, 2.0, -1.0]$

Tasks:

  1. Construct the full $2 \times 2$ pre-computed squared Euclidean distance lookup table $D_{\text{table}}[j, c]$ for $j \in \{1, 2\}$ and $c \in \{0, 1\}$.
  2. Compute the exact ADC squared Euclidean distance and Euclidean distance $d_{\text{ADC}}(\mathbf{q}, \mathbf{x})$ using the lookup table.
  3. Compute the exact uncompressed Euclidean distance between $\mathbf{q}$ and the reconstructed vector $\hat{\mathbf{x}} = [\mathbf{c}_{1, 1} \Vert \mathbf{c}_{2, 0}]$ to verify mathematical identity.
✓ Step-by-Step ADC Lookup Table Arithmetic

Step 1: Construction of Distance Lookup Table:
Partition the query vector into two 4-dimensional sub-vectors: $$\mathbf{q}_1 = [1.0, 2.0, -1.0, 0.5], \quad \mathbf{q}_2 = [0.0, 1.5, 2.0, -0.5]$$ Subspace 1 Distances ($j = 1$): To centroid $\mathbf{c}_{1, 0} = [0, 1, 0, 0]$: $$D_{\text{table}}[1, 0] = (1-0)^2 + (2-1)^2 + (-1-0)^2 + (0.5-0)^2 = 1.0 + 1.0 + 1.0 + 0.25 = \mathbf{3.25}$$ To centroid $\mathbf{c}_{1, 1} = [1, 2, -1, 1]$: $$D_{\text{table}}[1, 1] = (1-1)^2 + (2-2)^2 + (-1 - (-1))^2 + (0.5-1)^2 = 0 + 0 + 0 + (-0.5)^2 = \mathbf{0.25}$$
Subspace 2 Distances ($j = 2$): To centroid $\mathbf{c}_{2, 0} = [0, 1, 1, 0]$: $$D_{\text{table}}[2, 0] = (0-0)^2 + (1.5-1)^2 + (2-1)^2 + (-0.5-0)^2 = 0 + 0.25 + 1.0 + 0.25 = \mathbf{1.50}$$ To centroid $\mathbf{c}_{2, 1} = [0, 2, 2, -1]$: $$D_{\text{table}}[2, 1] = (0-0)^2 + (1.5-2)^2 + (2-2)^2 + (-0.5 - (-1))^2 = 0 + 0.25 + 0 + 0.25 = \mathbf{0.50}$$
Lookup Table Matrix $D_{\text{table}}$: $$D_{\text{table}} = \begin{bmatrix} 3.25 & 0.25 \\ 1.50 & 0.50 \end{bmatrix}$$

Step 2: Distance Evaluation via Table Lookups:
The database vector is encoded as code $C = [1, 0]$.
Evaluating squared distance requires summing the corresponding table entries: $$d_{\text{ADC}}^2(\mathbf{q}, \mathbf{x}) = D_{\text{table}}[1, C[1]] + D_{\text{table}}[2, C[2]] = D_{\text{table}}[1, 1] + D_{\text{table}}[2, 0]$$ $$d_{\text{ADC}}^2(\mathbf{q}, \mathbf{x}) = 0.25 + 1.50 = \mathbf{1.75}$$ Taking the square root: $$d_{\text{ADC}}(\mathbf{q}, \mathbf{x}) = \sqrt{1.75} \approx \mathbf{1.32288}$$ Notice: Evaluating distance to this vector required exactly 2 memory reads and 1 addition—zero floating-point multiplications!

Step 3: Direct Verification against Reconstructed Vector:
The quantized vector reconstructed from centroids is: $$\hat{\mathbf{x}} = [\mathbf{c}_{1, 1} \Vert \mathbf{c}_{2, 0}] = [1.0, 2.0, -1.0, 1.0, \quad 0.0, 1.0, 1.0, 0.0]$$ Compute direct squared Euclidean distance between $\mathbf{q}$ and $\hat{\mathbf{x}}$: $$\|\mathbf{q} - \hat{\mathbf{x}}\|^2 = (1-1)^2 + (2-2)^2 + (-1 - (-1))^2 + (0.5-1)^2 + (0-0)^2 + (1.5-1)^2 + (2-1)^2 + (-0.5-0)^2$$ $$= 0 + 0 + 0 + 0.25 + 0 + 0.25 + 1.0 + 0.25 = \mathbf{1.75}$$ $$\|\mathbf{q} - \hat{\mathbf{x}}\| = \sqrt{1.75} \approx \mathbf{1.32288}$$ Identity verified: ADC distance computed via lookups matches exact mathematical distance with 100% precision.

Problem 7.2.5 Expert Google Princeton

QUESTION: In Hierarchical Navigable Small World (HNSW) graphs, node insertion assigns an element $v$ to a maximum layer $l_v \in \mathbb{N}_0$ according to the probability distribution:

$$l_v = \left\lfloor -\ln(\xi) \cdot m_L \right\rfloor$$

where $\xi \sim \text{Uniform}(0, 1)$ and $m_L = \frac{1}{\ln M}$ is the normalization parameter ($M \ge 2$).

Tasks:

  1. Prove that the probability a node belongs to layer $l$ is given by $P(l_v \ge l) = M^{-l}$.
  2. Derive the expected maximum layer $\mathbb{E}[l_{\max}]$ across a graph containing $N$ vectors, and prove that $\mathbb{E}[l_{\max}] = \mathcal{O}(\log_M N)$.
  3. Assuming that on each layer $l$, greedy local routing requires at most a constant expected number of hops $C > 0$ to reach the local minimum before dropping to layer $l-1$, prove that the overall search complexity is strictly logarithmic: $\mathbb{E}[T_{\text{search}}] = \mathcal{O}(\log N)$.
✓ Mathematical Proof of Logarithmic HNSW Complexity

Step 1: Proof of Layer Assignment Probability:
Let $\xi \sim \text{Uniform}(0, 1)$. The maximum layer assigned is $l_v = \lfloor -\ln(\xi) \cdot m_L \rfloor$.
For any integer $l \ge 0$: $$l_v \ge l \iff -\ln(\xi) \cdot m_L \ge l \iff -\ln(\xi) \ge \frac{l}{m_L} \iff \ln(\xi) \le -\frac{l}{m_L}$$ Exponentiating both sides: $$\xi \le \exp\left(-\frac{l}{m_L}\right)$$ Since $\xi \sim \text{Uniform}(0, 1)$, $P(\xi \le z) = z$ for $z \in [0, 1]$. Therefore: $$P(l_v \ge l) = \exp\left(-\frac{l}{m_L}\right)$$ Substituting $m_L = \frac{1}{\ln M}$: $$P(l_v \ge l) = \exp\left(-l \ln M\right) = \exp\left(\ln M^{-l}\right) = \mathbf{M^{-l}}$$ Q.E.D. The probability of surviving to layer $l$ decays exponentially as $1 / M^l$, perfectly mirroring a geometric distribution with parameter $p = 1 - 1/M$.

Step 2: Expected Maximum Layer $\mathbb{E}[l_{\max}]$:
Let $N$ nodes be independently assigned layers $l_1, \dots, l_N$. The maximum layer is $l_{\max} = \max_{1 \le i \le N} l_i$.
The cumulative distribution function of $l_{\max}$ is: $$P(l_{\max} < l) = \prod_{i=1}^N P(l_i < l) = \big(1 - P(l_i \ge l)\big)^N = \left(1 - M^{-l}\right)^N$$ Using the expectation formula for non-negative discrete random variables: $$\mathbb{E}[l_{\max}] = \sum_{l=1}^\infty P(l_{\max} \ge l) = \sum_{l=1}^\infty \left[ 1 - \left(1 - M^{-l}\right)^N \right]$$ For large $N$, using the approximation $(1 - x)^N \approx e^{-Nx}$: $$1 - \left(1 - M^{-l}\right)^N \approx 1 - e^{-N M^{-l}}$$ Notice that when $M^l \ll N$, $e^{-N M^{-l}} \approx 0 \implies \text{term } \approx 1$.
When $M^l \gg N$, $e^{-N M^{-l}} \approx 1 - N M^{-l} \implies \text{term } \approx N M^{-l}$.
The transition point occurs when $M^l \approx N \implies l \approx \log_M N$.
Evaluating the summation rigorously yields: $$\mathbb{E}[l_{\max}] = \log_M N + \frac{\gamma}{\ln M} + \frac{1}{2} + o(1) = \mathbf{\mathcal{O}(\log_M N)}$$ where $\gamma \approx 0.5772$ is the Euler-Mascheroni constant. Q.E.D.

Step 3: Proof of Logarithmic Overall Search Complexity:
The greedy search starts at the global entry point on layer $l_{\max}$.
On each layer $l \in \{l_{\max}, l_{\max}-1, \dots, 1\}$, greedy routing moves along geometric links until discovering the node closest to $\mathbf{q}$ within that layer.
Because each layer is a Delaunay graph approximation (Navigable Small World) with bounded degree $\le M$, Kleinberg's small-world navigation theorem guarantees that the expected number of hops on each layer is bounded by a constant $C(M)$ independent of $N$.
Total expected hops across all upper layers down to Layer 0 is: $$\mathbb{E}[T_{\text{routing}}] \le \sum_{l=1}^{\mathbb{E}[l_{\max}]} C(M) = C(M) \cdot \mathbb{E}[l_{\max}] = C(M) \cdot \mathcal{O}\left(\frac{\ln N}{\ln M}\right) = \mathbf{\mathcal{O}(\log N)}$$ At Layer 0, a bounded beam search of size efSearch evaluates at most $2M \cdot \text{efSearch} = \mathcal{O}(1)$ additional candidates.
Summing all stages: $$\mathbb{E}[T_{\text{search}}] = \mathcal{O}(\log N) + \mathcal{O}(1) = \mathbf{\mathcal{O}(\log N)}$$ Q.E.D. HNSW reduces search across billions of vectors from linear to logarithmic time complexity!

✓ Mathematical Proof of Product Quantizer Error Decomposition

Step 1: Proof of Additive Error Decomposition:
Let $\mathbf{x} = [\mathbf{x}_1^\top, \dots, \mathbf{x}_m^\top]^\top \in \mathbb{R}^d$ and $q(\mathbf{x}) = [q_1(\mathbf{x}_1)^\top, \dots, q_m(\mathbf{x}_m)^\top]^\top \in \mathbb{R}^d$.
The squared Euclidean error is: $$\|\mathbf{x} - q(\mathbf{x})\|^2 = \sum_{i=1}^d \big(x_i - q(\mathbf{x})_i\big)^2$$ Group the coordinate indices according to the $m$ orthogonal subspaces $S_1, \dots, S_m$, where each subspace contains $d^* = d/m$ coordinates: $$\|\mathbf{x} - q(\mathbf{x})\|^2 = \sum_{j=1}^m \sum_{k \in S_j} \big(x_k - q_j(\mathbf{x}_j)_k\big)^2 = \sum_{j=1}^m \|\mathbf{x}_j - q_j(\mathbf{x}_j)\|^2$$ Taking expectations on both sides with respect to the probability distribution $p(\mathbf{x})$: $$\mathbb{E}\left[ \|\mathbf{x} - q(\mathbf{x})\|^2 \right] = \mathbb{E}\left[ \sum_{j=1}^m \|\mathbf{x}_j - q_j(\mathbf{x}_j)\|^2 \right]$$ By linearity of expectation: $$\mathbb{E}\left[ \|\mathbf{x} - q(\mathbf{x})\|^2 \right] = \sum_{j=1}^m \mathbb{E}\left[ \|\mathbf{x}_j - q_j(\mathbf{x}_j)\|^2 \right] \quad \text{Q.E.D.}$$

Step 2: Gersho's Asymptotic High-Rate Distortion Scaling:
According to Gersho's conjecture for optimal vector quantization in $\mathbb{R}^{d^*}$, for a codebook of size $K$, the mean squared error per subspace scales asymptotically as: $$\mathbb{E}\left[ \|\mathbf{x}_j - q_j(\mathbf{x}_j)\|^2 \right] \approx C(d^*) \cdot d^* \cdot K^{-2/d^*} \cdot \|\mathbf{x}_j\|_{L_{d^*/(d^*+2)}}$$ where $C(d^*)$ is the inertial profile constant of the optimal Voronoi tessellation in dimension $d^*$.
Summing over all $m$ identical sub-quantizers: $$\text{MSE}_{\text{total}} = \sum_{j=1}^m C(d^*) d^* K^{-2/d^*} \sigma^2 = m \cdot C(d^*) d^* K^{-2/d^*} \sigma^2 = \mathbf{d \cdot C(d^*) \cdot \sigma^2 \cdot K^{-2m/d}}$$ Key Insight: As the number of centroids $K$ increases, the distortion decreases exponentially at rate $K^{-2/d^*}$. To minimize distortion for a fixed bit budget $B_{\text{total}} = m \log_2 K$, the sub-vector dimension $d^*$ should be chosen to balance codebook capacity with quantization fidelity.

Step 3: Elimination of the Curse of Dimensionality:
Consider quantizing a 128-dimensional vector using a 64-bit budget ($2^{64}$ possible reconstruction values):

  • Standard Vector Quantization (VQ): Requires training a single codebook with $K_{\text{global}} = 2^{64} \approx 1.84 \times 10^{19}$ centroids! Storing this codebook requires $1.84 \times 10^{19} \times 128 \times 4\text{ bytes} \approx 9.4 \times 10^{21}\text{ bytes} \approx 9.4\text{ Zettabytes}$—more storage than the entire global internet! Training it via K-Means would take billions of years.
  • Product Quantization (PQ): Decomposes the space into $m = 8$ sub-vectors of dimension $d^* = 16$. Each sub-quantizer trains $K = 256$ centroids ($2^8$). The product space still contains $256^8 = 2^{64}$ effective centroids! $$\text{Total Codebook Storage} = 8 \times 256 \times 16 \times 4\text{ bytes} = \mathbf{131,072\text{ bytes (128 KB)}}!$$
Conclusion: Product Quantization provides an effective codebook of $2^{64}$ centroids using only 128 Kilobytes of memory and minutes of training time, completely breaking the curse of dimensionality!

Problem 7.2.7 Hard Google Pinecone

QUESTION: An engineer attempts to index unnormalized embedding vectors into an Approximate Nearest Neighbor graph using Maximum Inner Product Search (MIPS): $\arg\max_i \langle \mathbf{q}, \mathbf{x}_i \rangle$. The engineer uses standard Euclidean distance ($L_2$) HNSW without normalizing vectors to unit length ($\|\mathbf{x}\|_2 \neq 1$).

Which of the following statements correctly identifies why metric trees and spatial proximity graphs fail under unnormalized MIPS, and how the Neyshabur-Srebro transformation mathematically resolves it?

  1. Inner product fails because cosine similarity cannot be negative; the solution is adding $+1.0$ to all dot products.
  2. Inner product is not a valid mathematical metric: it does not satisfy non-negativity ($d(x, x) = 0$) or the Triangle Inequality ($d(x, z) \le d(x, y) + d(y, z)$). A vector with massive norm can have high inner product with distant vectors, breaking spatial pruning. The Neyshabur-Srebro transformation augments each vector with an extra dimension $\sqrt{U^2 - \|\mathbf{x}\|^2}$, converting MIPS into exact Euclidean distance on a $(d+1)$-dimensional hypersphere.
  3. MIPS fails because GPUs cannot compute dot products in parallel; the solution is switching to Manhattan ($L_1$) distance.
  4. MIPS works identically to $L_2$ distance regardless of vector norms because dot product is an affine transformation of Euclidean distance.
✓ Correct Answer: B (Exhaustive Metric Analysis)

Distractor Analysis:

  • Option A is False: Inner products can be negative (orthogonal vectors have 0, anti-parallel vectors have negative dot product). Adding $+1.0$ does not restore the triangle inequality.
  • Option B is Correct:
    • Geometric pruning algorithms (KD-trees, Ball-trees, VP-trees, HNSW) rely fundamentally on the Triangle Inequality: $d(x, z) \le d(x, y) + d(y, z)$. This property guarantees that if a node's center is far from query $\mathbf{q}$, none of its children can be close, allowing entire subtrees to be pruned safely.
    • The inner product $\langle \mathbf{q}, \mathbf{x} \rangle$ is a similarity measure, not a metric. Crucially: $$\|\mathbf{q} - \mathbf{x}\|^2 = \|\mathbf{q}\|^2 + \|\mathbf{x}\|^2 - 2\langle \mathbf{q}, \mathbf{x} \rangle$$ When $\|\mathbf{x}\|$ is constant (unit norm vectors), maximizing $\langle \mathbf{q}, \mathbf{x} \rangle$ is identical to minimizing $\|\mathbf{q} - \mathbf{x}\|$.
    • However, if vectors have variable norms, a vector with huge norm $\|\mathbf{x}\| = 1000$ can achieve a high inner product even if its angular alignment is poor! Metric pruning fails completely.
    • The Neyshabur-Srebro Transformation (2015): Let $U = \max_i \|\mathbf{x}_i\|$. Map each $d$-dimensional database vector to $d+1$ dimensions: $$\tilde{\mathbf{x}}_i = \left[ \mathbf{x}_i, \; \sqrt{U^2 - \|\mathbf{x}_i\|^2} \right] \implies \|\tilde{\mathbf{x}}_i\|^2 = U^2\text{ (Constant norm!)}$$ Augment query as $\tilde{\mathbf{q}} = [\mathbf{q}, 0]$. Then: $$\|\tilde{\mathbf{q}} - \tilde{\mathbf{x}}_i\|^2 = \|\mathbf{q}\|^2 + U^2 - 2\langle \mathbf{q}, \mathbf{x}_i \rangle$$ Minimizing $(d+1)$-dimensional $L_2$ distance is now rigorously identical to maximizing $d$-dimensional MIPS!
  • Option C is Ridiculous: GPUs are massively optimized for dot products (GEMM).
  • Option D is False: Dot product is equivalent to $L_2$ distance only when all vectors have identical norm.
Problem 7.2.8 Hard Amazon Pinecone

ASSERTION-REASONING:

Assertion (A): In a distributed vector database sharded horizontally across $S = 100$ independent worker nodes using document-partitioned sharding, a scatter-gather query architecture experiences severe Tail Latency Amplification, where an individual worker node SLA of $\text{p99} \le 10\text{ ms}$ results in a cluster-wide query p99 latency that routinely exceeds $30\text{ ms}$.

Reason (R): In document-partitioned scatter-gather routing, a client query must be broadcast to all $S$ shards simultaneously, and the aggregator cannot complete the response until the single slowest shard returns its local top-$k$ candidates; assuming independent worker latency distributions, the probability that a cluster query breaches the node-level p99 threshold is: $$P(\text{Cluster Latency} > T_{\text{p99}}) = 1 - (1 - 0.01)^{100} \approx 63.4\%$$

Options:

  1. Both (A) and (R) are true, and (R) is the correct explanation of (A).
  2. Both (A) and (R) are true, but (R) is NOT the correct explanation of (A).
  3. (A) is true, but (R) is false.
  4. (A) is false, but (R) is true.
✓ Correct Answer: A (Comprehensive Distributed Systems Analysis)

Deep Architectural Analysis:

Evaluation of Assertion (A): True.
Scatter-gather fan-out across dozens or hundreds of shards is one of the most notorious performance killers in distributed database engineering (Google Dean & Barroso, "The Tail at Scale", CACM 2013). Even though 99% of individual worker queries finish in $<10\text{ ms}$, overall user queries routinely wait for straggler nodes suffering from garbage collection pauses, noisy neighbor network contention, or CPU scheduling delays.

Evaluation of Reason (R): True & Explanatory.
Let $X_i$ be the latency of worker node $i \in \{1, \dots, S\}$. The overall query latency is governed by the order statistic: $$T_{\text{cluster}} = \max(X_1, X_2, \dots, X_S)$$ For the cluster query to complete within $T_{\text{p99}}$, every single one of the $S = 100$ nodes must finish within $T_{\text{p99}}$.
Under independence: $$P(T_{\text{cluster}} \le T_{\text{p99}}) = \prod_{i=1}^{100} P(X_i \le T_{\text{p99}}) = (0.99)^{100} \approx 0.3660 \quad (36.6\%)$$ The probability of at least one straggler node exceeding the p99 threshold is the complement: $$P(T_{\text{cluster}} > T_{\text{p99}}) = 1 - 0.3660 = \mathbf{0.6340 \quad (63.4\%!)!}$$ Nearly two-thirds of all queries suffer tail latency degradation!
Production Mitigations:

  1. Two-Level Hierarchical Routing: Use a coarse IVF clustering on the gateway node to route queries strictly to the top $P \ll S$ relevant shards (e.g. routing to only 4 shards instead of broadcasting to 100).
  2. Hedged Requests: If a shard has not responded within the 95th percentile duration ($7\text{ ms}$), dispatch a duplicate hedged request to a replica node and take whichever response arrives first.

import numpy as np

class ProductQuantizer:
    def __init__(self, d: int, m: int, k_sub: int = 256):
        assert d % m == 0, "Embedding dimension d must be divisible by sub-vector count m"
        self.d = d
        self.m = m
        self.d_sub = d // m
        self.k_sub = k_sub
        # Codebooks shape: (m, k_sub, d_sub)
        self.codebooks = np.zeros((m, k_sub, self.d_sub), dtype=np.float32)

    def fit(self, training_data: np.ndarray, num_iterations: int = 20):
        """Train k-means centroids for each orthogonal sub-vector space"""
        N = training_data.shape[0]
        for j in range(self.m):
            sub_data = training_data[:, j * self.d_sub : (j + 1) * self.d_sub]
            # Initialize centroids randomly from data samples
            indices = np.random.choice(N, size=self.k_sub, replace=False)
            centroids = sub_data[indices].copy()

            for _ in range(num_iterations):
                # Compute squared distances between samples and centroids: (N, k_sub)
                diff = sub_data[:, np.newaxis, :] - centroids[np.newaxis, :, :]
                dists = np.sum(diff ** 2, axis=-1)
                labels = np.argmin(dists, axis=1)

                # Update centroids
                for c in range(self.k_sub):
                    members = sub_data[labels == c]
                    if len(members) > 0:
                        centroids[c] = members.mean(axis=0)

            self.codebooks[j] = centroids

    def encode(self, vectors: np.ndarray) -> np.ndarray:
        """Compress float32 vectors into m uint8 bytes"""
        N = vectors.shape[0]
        codes = np.zeros((N, self.m), dtype=np.uint8)
        for j in range(self.m):
            sub_data = vectors[:, j * self.d_sub : (j + 1) * self.d_sub]
            diff = sub_data[:, np.newaxis, :] - self.codebooks[j][np.newaxis, :, :]
            dists = np.sum(diff ** 2, axis=-1)
            codes[:, j] = np.argmin(dists, axis=1).astype(np.uint8)
        return codes

    def compute_distance_table(self, query: np.ndarray) -> np.ndarray:
        """Pre-compute squared Euclidean distances between query sub-vectors and all centroids"""
        # Shape: (m, k_sub)
        distance_table = np.zeros((self.m, self.k_sub), dtype=np.float32)
        for j in range(self.m):
            q_sub = query[j * self.d_sub : (j + 1) * self.d_sub]
            diff = self.codebooks[j] - q_sub[np.newaxis, :]
            distance_table[j] = np.sum(diff ** 2, axis=-1)
        return distance_table

    def search_adc(self, query: np.ndarray, compressed_codes: np.ndarray, top_k: int = 5) -> tuple[np.ndarray, np.ndarray]:
        """Asymmetric Distance Computation (ADC) via lookup table"""
        dist_table = self.compute_distance_table(query) # (m, k_sub)
        
        # Accumulate distances using fast table lookups
        # compressed_codes has shape (N, m)
        N = compressed_codes.shape[0]
        scores = np.zeros(N, dtype=np.float32)
        for j in range(self.m):
            scores += dist_table[j, compressed_codes[:, j]]

        top_k_indices = np.argpartition(scores, top_k)[:top_k]
        top_k_indices = top_k_indices[np.argsort(scores[top_k_indices])]
        return top_k_indices, scores[top_k_indices]

if __name__ == "__main__":
    np.random.seed(42)
    N = 10000
    d = 128
    m = 16 # 16 sub-vectors of dimension 8 -> 16 bytes per vector (8x compression)
    data = np.random.randn(N, d).astype(np.float32)

    pq = ProductQuantizer(d=d, m=m, k_sub=256)
    pq.fit(data[:2000]) # Train on 2000 vectors
    codes = pq.encode(data)
    print(f"Compressed {N} vectors from {data.nbytes / 1e6:.2f} MB to {codes.nbytes / 1e6:.2f} MB ({data.nbytes / codes.nbytes:.1f}x compression)!")

    query = np.random.randn(d).astype(np.float32)
    top_indices, top_dists = pq.search_adc(query, codes, top_k=3)
    print(f"ADC Top-3 Neighbor IDs: {top_indices}, Squared Distances: {np.round(top_dists, 3)}")
